────────────────────────────────────────────────────────────────────────────────
PAGE 1A: LOGIN
Path   : front end/login/login.html
Files  : login.html, login.css, login.js
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  Entry gate to the entire system. No page is accessible without a valid JWT.

WHAT HAPPENS ON THIS PAGE:
  1. User sees a glassmorphism login form with company logo.
  2. Enters username and password.
  3. login.js calls: POST /api/v1/auth/login
  4. Backend (AuthController.java) validates credentials:
       – Username looked up in users table
       – BCrypt password hash compared
       – Role attached to JWT payload
  5. On success: JWT token stored in localStorage("token").
  6. Page redirects to: dashboard/dashboard.html
  7. On failure: Error message shown (invalid credentials / account locked).

WHAT DATA FLOWS OUT:
  – JWT token (stored in localStorage, used by every subsequent page)
  – User role (Admin / Tailor / Cashier / Supervisor / Receptionist)
  – User full name and profile (fetched separately by nav.js)

HOW IT CONNECTS TO OTHER PAGES:
  → Dashboard (auto-redirect on success)
  → ALL pages (JWT token in localStorage is required for every API call)
  → nav.js uses role to show/hide sidebar links

BACKEND:
  POST /api/v1/auth/login    → Returns { token, role, userId, name }
  POST /api/v1/auth/refresh  → Refreshes expired token

ROLES & WHAT THEY SEE AFTER LOGIN:
  Admin       → Full access to all 37 pages
  Receptionist→ Customers, Appointments, Enquiries, Orders (read-only)
  Tailor      → Production, Trials, Measurements (their orders only)
  Cashier     → Payments, Orders (read-only)
  Supervisor  → Production, QC, Workforce, Reports

PAGE 3B: MEASUREMENT 360 (Data Entry)
Path   : front end/Measurements/measurement360/
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  Record all body measurements for a customer. These are reused for every order.

MEASUREMENT FIELDS:
  UPPER BODY          LOWER BODY          GENERAL
  ──────────────────  ──────────────────  ──────────────────
  Bust/Chest          Waist               Height
  Shoulder Width      Hip                 Weight (optional)
  Back Length         Thigh               Neck circumference
  Sleeve Length       Knee to Ankle       Wrist circumference
  Arm circumference   Foot length (rare)  Posture notes

  GARMENT-SPECIFIC NOTES:
  – Custom measurement notes per garment type (e.g., "prefers loose waist")

WHAT HAPPENS:
  1. Customer linked by mobile number (from Customer360 or search)
  2. Tailor enters each measurement in cm or inches (toggle)
  3. Visual body diagram highlights each field as it's entered
  4. POST /api/v1/customers/{mobile}/body-measurements
  5. History is maintained – each save creates a new version with timestamp
  6. "View 3D" button → opens 3D Mannequin with new measurements

HOW IT CONNECTS:
  → 3D Mannequin (view live visualization)
  → Customer 360 (go back)
  → New Order (measurements auto-attached when creating order)


────────────────────────────────────────────────────────────────────────────────
PAGE 3C: 3D MANNEQUIN VISUALIZER
Path   : front end/Measurements/3D MANNEQUIN/mannequin3d.html
Files  : mannequin3d.html, mannequin3d.css, mannequin3d.js
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  Interactive 3D visualization of the customer's body shape built from
  their actual measurements. Helps tailors identify fit issues before cutting.

HOW IT WORKS:
  1. Customer selected from search dropdown
  2. GET /api/v1/customers/{mobile}/body-measurements fetched
  3. Three.js r134 renders a procedural female mannequin
  4. Cylinder geometries morphed based on:
       – bust radius       → chest cylinder radius
       – waist measurement → waist cylinder radius (narrowed)
       – hip measurement   → hip cylinder radius
       – height            → overall scale
       – shoulder width    → shoulder span
       – sleeve length     → arm cylinder height
  5. OrbitControls: 360° rotation, scroll to zoom, right-click to pan
  6. FIT SCORE calculated by comparing to ideal proportions:
       – Green (90-100%): Excellent fit, no alterations likely
       – Yellow (70-89%): Minor alterations expected
       – Red   (<70%):   Significant fitting challenges, flag to supervisor
  7. Side panel shows measurement list with live values
  8. "Compare" mode: load two customers side by side
  9. Alteration suggestions generated based on proportion differences
  10. Measurement history timeline at bottom

WHAT IT CONNECTS TO:
  → Trials & Alterations (compare with trial result)
  → Measurement 360 (update measurements)
  → Customer 360 (go back to profile)


────────────────────────────────────────────────────────────────────────────────
PAGE 4A: DESIGN STUDIO
Path   : front end/DesignStudio/design-studio.html
Files  : design-studio.html, design-studio.css, design-studio.js
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  Canvas-based garment design tool. Designer and customer together
  visualize and finalize the garment design before ordering.

FEATURES:
  – Garment template library (kurta, salwar, saree blouse, suit jacket, etc.)
  – Fabric swatch selector with texture preview (from fabrics-materials DB)
  – Stitch pattern library (plain, pintuck, smocking, etc.)
  – Embroidery placement tool (drag-drop onto garment silhouette)
  – Color palette picker with seasonal color suggestions
  – Neckline & sleeve style picker
  – Lining and interlining options
  – Save design as named JSON record (POST /api/v1/designs)
  – Print-ready design sheet: front view, back view, fabric swatch, notes

WORKFLOW ON THIS PAGE:
  1. Select garment type (base template)
  2. Pick fabric from catalog (pulls from fabrics DB)
  3. Choose stitch pattern, neckline, sleeve style
  4. Add embroidery / embellishments by dragging onto canvas
  5. Set colors
  6. Preview front & back
  7. Save design with a name (e.g., "Blue Silk Kurta – Mrs. Fatima")
  8. Design ID returned, attached to upcoming order

HOW IT CONNECTS:
  → Fabrics & Materials (fabric selection)
  → New Order (design attached to order)
  → Garments (base garment template)
  → Production (design sheet sent to tailor)

PAGE 6: PRODUCTION MANAGEMENT
Path   : front end/production/production.html
Sub    : front end/production/stages/
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  Track every active order through its manufacturing lifecycle.

PRODUCTION STAGES:
  ┌────────────────────────────────────────────────────────┐
  │  Stage 1 – CUTTING                                     │
  │    Fabric issued from inventory                        │
  │    Tailor assigned                                     │
  │    Pattern pieces cut according to measurements        │
  │    Design sheet displayed from Design Studio           │
  ├────────────────────────────────────────────────────────┤
  │  Stage 2 – STITCHING                                   │
  │    Pattern pieces joined                               │
  │    Primary structure of garment formed                 │
  │    Inner seams, darts, pleats completed                │
  ├────────────────────────────────────────────────────────┤
  │  Stage 3 – EMBROIDERY / EMBELLISHMENT                  │
  │    Hand or machine embroidery                          │
  │    Beading, mirror work, sequins, lace attachment      │
  │    Embellishment placement follows Design Studio spec  │
  ├────────────────────────────────────────────────────────┤
  │  Stage 4 – FINISHING & IRONING                         │
  │    Buttons, hooks, zippers attached                    │
  │    Final stitching checks                              │
  │    Steam pressing and shaping                          │
  │    Internal labeling                                   │
  ├────────────────────────────────────────────────────────┤
  │  Stage 5 – READY FOR TRIAL ✅                          │
  │    Garment complete, trial appointment triggered       │
  │    Order status → "Ready for Trial"                    │
  └────────────────────────────────────────────────────────┘

PRODUCTION BOARD FEATURES:
  – All active orders in a scrollable board
  – Progress bar showing current stage (1–5)
  – Time elapsed in current stage
  – Delay alerts (if overdue)
  – Tailor workload sidebar (how many orders per tailor)
  – Click order → View Order detail

PRODUCTION STAGES SUB-PAGE:
  – Breakdown view per stage
  – How many orders are in each stage
  – Average time per stage (performance metric)
  – Bottleneck detection (which stage is slowest)

API CALLS:
  GET  /api/v1/production                → All orders in production
  PUT  /api/v1/production/{id}/stage     → Advance to next stage
  PUT  /api/v1/production/{id}/assign    → Assign tailor to order
  PUT  /api/v1/inventory/{id}            → Deduct fabric at cutting stage

HOW IT CONNECTS:
  → Workforce (assign tailors)
  → Orders (order status updated as stages advance)
  → Inventory (fabric deducted at Stage 1)
  → Trials (auto-trigger when Stage 5 complete)
  → Design Studio (design spec shown during stitching)

PAGE 7B: TRIALS & ALTERATIONS
Path   : front end/trials-alterations/trials-alterations.html
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  Record fitting trial sessions. If the garment doesn't fit, document
  alteration instructions and send back to production.

TRIAL RECORD FORM:
  – Order ID (auto-linked from appointment or search)
  – Trial round number (Trial 1, Trial 2, etc.)
  – Trial date
  – Overall result: APPROVED / NEEDS ALTERATION

  FIT ASSESSMENT BY AREA:
  ┌─────────────────────────────────────────────────────────┐
  │  Area          │ Rating      │ Notes                    │
  │  ──────────────│─────────────│──────────────────────────│
  │  Shoulder fit  │ ✅/⚠️/❌    │ e.g., "widen by 1cm"     │
  │  Chest/Bust    │ ✅/⚠️/❌    │ e.g., "take in 2cm"      │
  │  Waist         │ ✅/⚠️/❌    │                          │
  │  Hip           │ ✅/⚠️/❌    │                          │
  │  Length        │ ✅/⚠️/❌    │ e.g., "shorten by 3cm"   │
  │  Sleeve        │ ✅/⚠️/❌    │                          │
  │  Neckline      │ ✅/⚠️/❌    │                          │
  │  Embellishment │ ✅/⚠️/❌    │                          │
  └─────────────────────────────────────────────────────────┘

  – Customer signature / acknowledgment
  – Photo attachment (optional – before/after photos of fit issues)

WHAT HAPPENS AFTER:
  IF APPROVED:
    → Order status updated to "Trial Done"
    → Next step: Quality Control
  IF NEEDS ALTERATION:
    → Alteration instructions saved
    → Order sent back to production (specific stage depends on alteration type)
    → Trial round counter incremented
    → Appointment booked for next trial

3D MANNEQUIN USAGE DURING TRIALS:
  – Open 3D view alongside trial assessment
  – Visually compare current measurements vs design spec
  – Use Fit Score to quantify issues

API:
  POST /api/v1/trials      → Record trial result
  GET  /api/v1/trials      → All trial records (filterable by order)

HOW IT CONNECTS:
  → Production (send back for alteration)
  → Quality Control (proceed after approval)
  → Appointments (trial booked as appointment)
  → 3D Mannequin (visual fit comparison)
  → View Order (trial history shown on order detail)


────────────────────────────────────────────────────────────────────────────────
PAGE 8: QUALITY CONTROL
Path   : front end/quality-control/quality-control.html
────────────────────────────────────────────────────────────────────────────────

PURPOSE:
  Final inspection before any garment is packaged for delivery.
  QC supervisor checks the completed garment against all quality standards.

QC CHECKLIST (scored 1–5 or Pass/Fail):
  1. Stitching uniformity (no loose threads, even seams)
  2. Measurement accuracy (matches order specification within tolerance)
  3. Embroidery/embellishment placement and quality
  4. Fabric cleanliness (no stains, pulls, or runs)
  5. Buttons, hooks, zippers (correctly placed, functioning)
  6. Lining neatness (if applicable)
  7. Steam press quality (well-shaped, no creases in wrong places)
  8. Internal labelling (brand label, care instructions)
  9. Packaging readiness (ready for bag/box)

QC RESULT:
  PASS (all items score 4+ or Pass):
    → Order status → "Ready to Deliver"
    → Delivery module unlocked for this order
  FAIL (one or more items fail):
    → Failed areas documented with specific notes
    → Order sent back to appropriate production stage
    → QC record saved with "Fail" status
    → Re-inspection required after rework

ADDITIONAL FEATURES:
  – QC history for each order (how many attempts, who inspected)
  – Inspector name recorded (linked to logged-in user)
  – Date and time of inspection
  – Photos of issues can be attached

API:
  GET  /api/v1/quality-control      → All QC records
  POST /api/v1/quality-control      → Submit QC result

HOW IT CONNECTS:
  → Trials (must be approved before QC)
  → Delivery (unlocked only after QC pass)
  → Production (send back if QC fails)
  → View Order (QC history shown)
