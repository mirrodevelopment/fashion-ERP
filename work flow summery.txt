SECTION 3 – HOW THE FRONTEND WORKS (SPA ARCHITECTURE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The frontend is a Vanilla JavaScript Single-Page-style App.
Every page (HTML file) follows the same bootstrap pattern:

  1. Page HTML loads its own CSS.
  2. Page HTML includes <script> tag loading fragments.js (the shared shell loader).
  3. fragments.js dynamically injects:
       – navbar.html    (top bar with user info, notifications, company logo)
       – sidebar.html   (left navigation menu with all module links)
       – footer.html    (bottom bar)
  4. nav.js activates the correct sidebar link based on the current URL path.
  5. company-bridge.js fetches company name/logo from backend and injects into navbar.
  6. system-bridge.js injects global system settings (currency, timezone, theme).
  7. Page's own .js file runs its business logic and calls api.js for data.

KEY SHARED FILES:
  • api.js           → All REST calls go through this. Handles:
                         - Base URL (http://localhost:8080/api/v1)
                         - Attaching Bearer JWT token to every request
                         - Token refresh / auto-login for dev mode
                         - CRUD helpers: api.get(), api.post(), api.put(), api.delete()
  • fragments/nav.js → Controls sidebar navigation, active highlighting, and
                       logout functionality.

SECTION 4 – END-TO-END WORKFLOW (HOW PAGES CONNECT)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Below is the complete business workflow from a customer walking in to garment delivery:

────────────────────────────────────────────────────────────────────────────────
STEP 1 : USER LOGS IN
────────────────────────────────────────────────────────────────────────────────
  Page     : login/login.html
  Action   : User enters username & password → login.js calls POST /api/v1/auth/login
  Response : JWT token received → stored in localStorage("token")
  Next     : Redirect to dashboard/dashboard.html
  Connects to: ALL pages (every page reads this token via api.js)

────────────────────────────────────────────────────────────────────────────────
STEP 2 : DASHBOARD (Home Overview)
────────────────────────────────────────────────────────────────────────────────
  Page     : dashboard/dashboard.html
  Shows    : KPI cards (total customers, active orders, pending payments,
             today's appointments, production status, revenue summary)
  Data     : dashboard.js calls GET /api/v1/dashboard/summary
  Links to : Every module through sidebar nav links (fragments/sidebar.html)
  Shortcuts: Clicking a KPI card navigates directly to that module

────────────────────────────────────────────────────────────────────────────────
STEP 3 : ENQUIRY CAPTURE (Walk-in lead)
────────────────────────────────────────────────────────────────────────────────
  Page     : enquiries/enquiries.html
  Purpose  : Record a walk-in customer enquiry before they become a full customer
  Actions  : Add enquiry → POST /api/v1/enquiries
             View list   → GET  /api/v1/enquiries
  Connects to: Appointments (schedule a follow-up meeting)
               Customer module (convert enquiry to full customer)

────────────────────────────────────────────────────────────────────────────────
STEP 4 : APPOINTMENT SCHEDULING
────────────────────────────────────────────────────────────────────────────────
  Page     : appointments/appointments.html
  Purpose  : Book a fitting / consultation appointment
  Actions  : Create appointment → POST /api/v1/appointments
             Calendar view      → GET  /api/v1/appointments
  Connects to: Customer module (customer linked to appointment)
               Measurements module (appointment for measurement session)
               Orders module (appointment for trial fitting)

────────────────────────────────────────────────────────────────────────────────
STEP 5 : CUSTOMER REGISTRATION
────────────────────────────────────────────────────────────────────────────────
  Page A   : customer/customer-overview/ → Lists all customers, search & filter
             Calls GET /api/v1/customers
  Page B   : customer/new-customer/      → New customer registration form
             Calls POST /api/v1/customers
  Page C   : customer/Customer360/       → Full 360° view of one customer:
               - Personal details
               - All their orders
               - Measurement history
               - Payment history
               - Appointment history
             Calls GET /api/v1/customers/{mobile}
  Connects to:
    → Measurements module  (take measurements right after registration)
    → Orders module        (create order for this customer)
    → Appointments module  (link appointments to this customer)
    → Payments module      (view outstanding balance)

────────────────────────────────────────────────────────────────────────────────
STEP 6 : BODY MEASUREMENTS
────────────────────────────────────────────────────────────────────────────────
  Page A   : Measurements/measurement-overview/  → All measurement records list
             Calls GET /api/v1/customers/measurements
  Page B   : Measurements/measurement360/        → Full measurement data entry
             (bust, waist, hips, shoulder, sleeve, height, etc.)
             Calls POST /api/v1/customers/{mobile}/body-measurements
             Calls GET  /api/v1/customers/{mobile}/body-measurements
  Page C   : Measurements/3D MANNEQUIN/mannequin3d.html
             → Renders a live 3D parametric mannequin using Three.js
             → Pulls measurements from the database in real time
             → Morphs cylinder geometry to match customer body shape
             → Calculates fit score and shows alteration suggestions
             Calls GET /api/v1/customers/{mobile}/body-measurements
  Connects to:
    → Customer module  (measurements are always linked to a customer)
    → Orders module    (measurements are attached to an order at creation)
    → Trials module    (fit check during trial compares to these measurements)

────────────────────────────────────────────────────────────────────────────────
STEP 7 : GARMENT & DESIGN SETUP (One-time catalog)
────────────────────────────────────────────────────────────────────────────────
  Page A   : garments/garments.html     → Garment type catalog (kurta, suit, etc.)
  Page B   : garments/new-garment/      → Add new garment type
  Page C   : garments/garaments 360/    → Garment detail with linked orders
             Calls GET/POST /api/v1/garments

  Page D   : collections/collections.html → Seasonal collection management
             Calls GET/POST /api/v1/collections

  Page E   : DesignStudio/design-studio.html
             → Canvas-based design tool for custom garment designs
             → Supports fabric swatch selection, stitch patterns, embroidery
             → Saves design as JSON linked to garment/order
             Calls GET/POST /api/v1/designs

  Connects to:
    → Orders module   (customer picks garment + design when placing order)
    → Fabrics module  (design references specific fabrics)
    → Production      (design spec sent to tailor during production)

────────────────────────────────────────────────────────────────────────────────
STEP 8 : FABRIC & MATERIAL MANAGEMENT
────────────────────────────────────────────────────────────────────────────────
  Page     : fabrics-materials/fabrics-materials.html
  Purpose  : Catalog of all fabrics with type, color, stock quantity, cost
  Actions  : Add/edit/delete fabrics → POST/PUT/DELETE /api/v1/fabrics
             Stock check             → GET /api/v1/fabrics/stock
  Connects to:
    → Inventory module (fabric stock levels tracked here)
    → Purchases module (when fabric stock is low, trigger purchase)
    → Orders module    (fabric selected when creating an order)
    → Design Studio    (fabric swatches shown in design tool)
    → Production       (fabric issued to tailor during cutting stage)

────────────────────────────────────────────────────────────────────────────────
STEP 9 : ORDER PLACEMENT
────────────────────────────────────────────────────────────────────────────────
  Page A   : orders/order-overview/  → All orders with status board (Kanban view)
             Calls GET /api/v1/orders
  Page B   : orders/new-order/       → Multi-step order creation wizard:
               Step 1 – Select Customer
               Step 2 – Select Garment(s) & Design
               Step 3 – Attach Measurements
               Step 4 – Select Fabric & Material
               Step 5 – Set delivery date & priority
               Step 6 – Payment advance collection
             Calls POST /api/v1/orders
  Page C   : orders/view-order/      → Full order detail with status timeline:
               - Order info & items
               - Assigned tailor
               - Current production stage
               - Trial dates
               - Payment ledger
               - Delivery status
             Calls GET /api/v1/orders/{orderId}
  Connects to:
    → Customer module     (every order belongs to a customer)
    → Measurements module (measurement ID attached to order)
    → Garment module      (garment type selected)
    → Design Studio       (design linked to order)
    → Fabric module       (fabric selection)
    → Payments module     (advance payment recorded at order creation)
    → Production module   (order moves to production after placement)
    → Appointments module (trial fitting appointments linked to order)
    → Delivery module     (delivery created when order is completed)

────────────────────────────────────────────────────────────────────────────────
STEP 10 : PRODUCTION MANAGEMENT
────────────────────────────────────────────────────────────────────────────────
  Page     : production/production.html
  Purpose  : Track each order through production stages:
               Stage 1 – Cutting
               Stage 2 – Stitching
               Stage 3 – Embroidery / Embellishment
               Stage 4 – Finishing / Ironing
               Stage 5 – Ready for Trial
  Actions  : Update stage → PUT /api/v1/production/{orderId}/stage
             Assign tailor → PUT /api/v1/production/{orderId}/assign
             View board    → GET /api/v1/production
  Sub-pages: production/stages/ → Detailed stage-level views
  Connects to:
    → Workforce module (tailors assigned to production tasks here)
    → Orders module    (order status updated as production progresses)
    → Quality Control  (QC check triggered after finishing stage)
    → Trials module    (trial scheduled after "Ready for Trial" stage)
    → Inventory module (fabric issued from inventory at cutting stage)

────────────────────────────────────────────────────────────────────────────────
STEP 11 : TRIALS & ALTERATIONS
────────────────────────────────────────────────────────────────────────────────
  Page     : trials-alterations/trials-alterations.html
  Purpose  : Record fitting trial results and any alteration notes
  Actions  : Record trial result → POST /api/v1/trials
             View trials         → GET  /api/v1/trials
  Connects to:
    → Orders module      (trial linked to specific order)
    → Customer module    (trial appointment involves the customer)
    → Appointments module (trial session booked as an appointment)
    → Measurements module (fit compared against stored measurements)
    → Production module   (alteration sends garment back to production)
    → 3D Mannequin        (fit visualized against 3D body model)

────────────────────────────────────────────────────────────────────────────────
STEP 12 : QUALITY CONTROL
────────────────────────────────────────────────────────────────────────────────
  Page     : quality-control/quality-control.html
  Purpose  : Final QC inspection before delivery is approved
  Actions  : Submit QC pass/fail → POST /api/v1/quality-control
             View QC records      → GET  /api/v1/quality-control
  Connects to:
    → Production module (QC triggered after finishing stage)
    → Orders module     (order only moves to delivery after QC pass)
    → Delivery module   (delivery enabled after QC approval)

────────────────────────────────────────────────────────────────────────────────
STEP 13 : PAYMENTS
────────────────────────────────────────────────────────────────────────────────

SECTION 7 – HOW AUTHENTICATION FLOWS THROUGH THE APP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. User submits credentials on login.html
  2. login.js → POST /api/v1/auth/login
  3. Spring Security (AuthController) validates → generates JWT
  4. JWT stored in localStorage as "token"
  5. Every subsequent API call in api.js reads this token:
       headers: { Authorization: "Bearer " + token }
  6. JwtAuthFilter (Spring Security) intercepts every request:
       - Validates token signature & expiry
       - Sets SecurityContext (current user)
  7. If token is missing or expired → 401 Unauthorized
  8. api.js auto-redirects to login.html on 401
  9. Role-based access: nav.js hides sidebar items based on user role

SECTION 10 – HOW TO START THE APPLICATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  PREREQUISITES:
    - Java 21 installed
    - PostgreSQL 17 installed and running (service: postgresql-x64-17)
    - Database "fashion_erp" created

  STARTUP (Option 1 – One click):
    Double-click start.bat
    This starts the PostgreSQL service and runs the Spring Boot backend.

  STARTUP (Option 2 – Manual):
    1. Start PostgreSQL:
         net start postgresql-x64-17
    2. Start Spring Boot:
         mvnw.cmd spring-boot:run
    3. Open browser to any frontend HTML file directly
         (e.g., front end/login/login.html)

  SEED DEMO DATA:
    Double-click seed_demo.bat
    This inserts sample customers, orders, measurements, etc.

  PURGE DATABASE:
    Double-click purge_db.bat
    WARNING: This deletes all data and re-creates tables.

  BACKEND HEALTH CHECK:
    Open browser: http://localhost:8080/api/v1/dashboard/summary
    Should return JSON with KPI data.
