1.1 ARCHITECTURE & DESIGN DECISIONS
--------------------------------------------------------------------------------
1. Framework & Stack:
   - Backend : Spring Boot 4.1.1 on Java 17 with Spring Data JPA & Hibernate 6.
   - Database: PostgreSQL (fashion_erp) with Flyway database migration versioning.
   - Security: Spring Security 6 with stateless HMAC-SHA256 JWT tokens (24h TTL).
   - Frontend: 100% Pure Vanilla ES6+ JavaScript, CSS3 custom properties (:root),
               and semantic HTML5. No npm, Webpack, Vite, or Node build step.

2. Zero-Recompile Frontend Live Development:
   - WebMvcConfig.java implements addResourceHandlers mapping "/front end/**"
     directly to the file system path: Paths.get("front end").toAbsolutePath().
   - Modifying any HTML, CSS, or JS file in "front end/" immediately reflects on
     browser refresh without rebuilding the Spring Boot JAR or Maven compile.

3. Aesthetics & Luxury Atelier Design System:
   - Theme defined in "front end/fragments/theme/theme.css" (1,725 lines).
   - Palette: Warm Dark luxury charcoal/espresso (#242522, #1F211F, #3A3732),
     accented by Haute Couture Neon-Lime (#B8FF3D) and emerald/amber/rose statuses.
   - Glassmorphism: Semi-transparent backdrop-filtered cards with subtle borders.

2.2 TABLE SPECIFICATIONS SUMMARY
--------------------------------------------------------------------------------
01. customers:
    - Master client identity using mobile_number (VARCHAR 30) as natural PK.
    - Fields: name, first_name, last_name, salutation, gender, email, alt_phone,
      instagram_handle, preferred_channel, dob, anniversary, location, street_address,
      city, state, pincode, landmark, avatar_url, tier (REGULAR/SILVER/GOLD/VIP),
      total_spend, balance, credit_limit, favorite_garment, fit_preference,
      fabric_allergies, measurements_on_file, notes, created_at, updated_at.

02. customer_notes:
    - Timestamped CRM diary entries tied to customer_mobile.
    - Fields: id, customer_mobile (FK), author, note_text, created_at.

03. customer_body_measurements:
    - 34 Anatomical Tailoring Measurement Points with garment versioning.
    - Fields: id, customer_mobile (FK), customer_name, garment_type, measurement_type,
      is_current, version, unit ('in'/'cm'), shoulder, bust, under_bust, waist, hip,
      blouse_length, top_length, full_length, skirt_length, pant_length, armhole,
      upper_arm, sleeve_length, sleeve_round, elbow_round, wrist_round,
      front_neck_depth, back_neck_depth, bust_point, apex_to_apex, cross_front,
      cross_back, crotch_depth, thigh_round, knee_round, calf_round, ankle_round,
      notes, created_at, updated_at.

04. customer_measurements:
    - Legacy key-value unstructured measurements: id, customer_mobile, garment_type,
      measurement_data, created_at.

05. measurement_profiles & 06. measurement_points:
    - Reusable named measurement profiles (e.g. "Bridal 2026") containing discrete
      measurement points (name, numeric value, unit).
  
07. orders:
    - Core garment production order ledger: id, order_code (ORD-YYYY-XXXX),
      customer_mobile (FK), customer_name, garment_type, garment_desc, collection,
      order_date, expected_delivery_date, delivered_date, advance_paid, total_amount,
      balance_amount, amount, status (PENDING, IN_PROGRESS, READY, DELIVERED, CANCELLED),
      current_stage, due_date, notes, production_notes, reference_images (Array/CSV),
      qc_rework_count, created_at, updated_at.

08. order_progress_stages:
    - Milestone timestamps: id, order_id (FK), stage, completed_at, completed_by, notes.

09. production_stages:
    - Real-time per-order Kanban pipeline stages: id, order_id (FK), stage_name,
      sort_order, status (NOT_STARTED, IN_PROGRESS, COMPLETED), assigned_to (FK),
      started_at, completed_at, notes, created_at.

10. stage_definitions & 11. stage_definition_employees:
    - Dynamic customizable stage blueprints: id, stage_key (UNIQUE), display_name,
      sort_order, sla_hours, default_role, image_url, active. Maps specialist
      employees to specific stage definitions.

12. qc_checklists:
    - Quality assurance inspection line items: id, order_id (FK), check_point,
      sort_order, result (PENDING, PASS, FAIL, REWORK), remarks, checked_by (FK),
      checked_at.

13. trials & 14. trial_alterations:
    - Client fitting sessions: id, trial_code (TRL-TIMESTAMP), order_id (FK),
      order_code, customer_mobile (FK), customer_name, garment_type, collection,
      trial_date, trial_time, stage, status (TODAY, UPCOMING, COMPLETED,
      RETRIAL_SCHEDULED), fit_status (PENDING, PERFECT, MINOR_ALTERATIONS,
      MAJOR_ALTERATIONS), trial_attempt, alteration_count, customer_feedback,
      customer_rating, fit_preference, designer_name, delivery_date, specs, notes.
    - Alterations sub-items: id, trial_id (FK), area, instruction, completed flag.

15. inventory_items & 16. stock_movements:
    - Fabric rolls, trims, threads: id, item_code (ITEM-XXXX), name, category,
      variant, unit, stock_qty, reserved_qty, reorder_level, purchase_price,
      selling_price, status, composition, weave, width, gsm, hsn_code, origin,
      location, lead_time, supplier_name, supplier_contact, image_url, notes.
    - Immutable audit ledger: id, item_id (FK), movement_type (RECEIPT, ISSUE,
      ADJUSTMENT), quantity, reference, notes, moved_by, created_at.

17. suppliers:
    - Textile mills & trim vendors: id, supplier_code, name, contact_person,
      phone, email, address, category, payment_terms, gstin, rating, notes.

18. purchase_orders & 19. purchase_order_items:
    - Procurement orders: id, po_number (PO-XXXX), supplier_id (FK), order_date,
      expected_delivery_date, total_amount, status (DRAFT, ORDERED, RECEIVED,
      CANCELLED). Line items link to inventory_items with quantities & unit costs.

20. payments & 21. payment_transactions:
    - Financial settlement: id, order_id (FK), customer_mobile (FK), total_amount,
      advance_paid, balance_amount, status (PENDING, PARTIAL, PAID, REFUNDED),
      invoice_number. Transaction logs record payment_method (CASH, CARD, UPI,
      NET_BANKING), transaction_ref, recorded_by, created_at.

22. appointments:
    - Calendar bookings: id, customer_mobile (FK), customer_name, order_id (FK),
      appointment_type (CONSULTATION, MEASUREMENT, TRIAL, DELIVERY), appointment_date,
      time_slot, status (CONFIRMED, COMPLETED, CANCELLED, NO_SHOW), stylist_notes.

23. enquiries:
    - Sales CRM leads: id, customer_name, phone, email, garment_type, status (NEW,
      IN_DISCUSSION, QUOTATION_SENT, CONVERTED, CLOSED), source (Instagram, WhatsApp,
      Walk-in, Referral), fabric_brought, budget, follow_up_date, notes,
      converted_order_id (FK).

24. designs:
    - Atelier design lookbook: id, title, design_code, category, description,
      fabric_recommendations, estimated_price, tags, front_image_url, back_image_url,
      customer_mobile (FK), order_id (FK).

25. employees:
    - Master artisan & staff directory: id, employee_code, name, role, department
      (Cutting, Embroidery, Stitching, Finishing, Quality Control), phone, email,
      hourly_rate, daily_capacity_hours, status (ACTIVE, ON_LEAVE, INACTIVE),
      avatar_url.

26. app_users:
    - System operators: id, username (UNIQUE), password_hash (BCrypt 12), full_name,
      email, role (ADMIN, MANAGER, TAILOR, CASHIER), active flag.

[7] COMPLETE BUSINESS LIFECYCLE WORKFLOWS
================================================================================

7.1 SCENARIO A: BESPOKE BRIDAL ORDER (LEAD TO DISPATCH)
1. Lead Intake: Client inquires via Instagram -> EnquiryController records lead.
2. Conversion : Lead converts to Customer -> phone number stored as primary key.
3. Measurement: Master tailor records 34 anatomical points in body measurements.
4. Booking    : Order created in new-order -> OrderService auto-seeds ProductionStages.
5. Production : Order progresses through Cutting, Embroidery, Stitching on Kanban.
6. Fitting    : Trial session conducted -> fit marked PERFECT -> advances to QC.
7. Inspection : QC Lead approves checklist -> order moves to READY_TO_DELIVER.
8. Dispatch   : Delivery Command Centre verifies zero balance and dispatches garment.

7.2 SCENARIO B: FITTING TRIAL DEFECT & QC REWORK REWIND
1. Trial Fitting: Client notes waist is tight -> Alteration punch list logged.
2. Retrial      : TrialService increments trial_attempt and schedules Retrial #2.
3. Tailor Fix   : Tailor adjusts seam -> Retrial confirms PERFECT fit -> moves to QC.
4. QC Inspection: QC audit detects loose embroidery -> Inspector triggers Rework.
5. Rewind       : QcController increments qc_rework_count and rewinds order stage to
                  EMBROIDERY with inspector defect notes.
6. Re-inspection: Artisan fixes embroidery -> QC re-audits and passes order.
7. Completion   : Order advances to READY_TO_DELIVER with clean audit history.
